这是当前硬件版本的中文入口。详细逐脚表见
[02-MCU-Pinout.md](02-MCU-Pinout.md)，按网络反查全部端点见

## 当前硬件

- 主控：STM32L452RCT6，3.3 V。
- 麦克风：2 颗 SPH0655LM4H-1-8，1.8 V PDM，共用时钟和数据线。
- 存储：microSD，SPI1 模式。
- USB：Type-C USB 2.0 Device，可充电、传文件、进入 STM32 ROM DFU。
- 电池：单节带保护板的 3.7 V 400 mAh 聚合物锂电池。
- 主电源：TPS63031 将 BAT 升降压为 3.3 V。
- 麦克风电源：XC6206P182MR 将 3.3 V 降为 1.8 V。
- 时钟：32.768 kHz 晶振给 STM32 RTC 使用。

## 必须先知道的硬件问题

当前原理图、导出网表和 PCB 都已将 `PDM_DATA_3V3` 接到 PB12（33 脚，
DFSDM1_DATIN1），PB1（27 脚）现在是 NC。这个引脚分配满足 STM32 DFSDM 单数据线
双麦克风所需的连续 Channel 1/Channel 0 结构，但还没有经过固件和实物录音验证。

固件必须：

1. 使用 Channel 1 直接接收 `DATIN1`。
2. 将 Channel 0 重定向到 Channel 1 的串行输入。
3. 两个通道设置为相反采样边沿，并使用独立 DFSDM Filter/DMA 验证声道身份。

USB 插入检测的 R9、R10、C26 也已经放置并连接到 PCB。最新 API DRC 仍报告 58 个
间距错误和 1 个原理图/PCB 网表不一致错误，且 PCB 仍没有 GND 铺铜，所以不能直接
当作量产版本。

## 上电与下载

第一次上电先用 3.7 V 限流电源接 BAT/GND，不要先接锂电池。确认 3V3、1V8 无短路、
电压正确且芯片不发热后，再连接下载工具。

USB ROM DFU 操作顺序：

1. 按住 BOOT 按钮。
2. 按下并松开 RESET。
3. 松开 BOOT。
4. 连接 Type-C，用 STM32CubeProgrammer 选择 USB/DFU 下载。

Type-C 插入本身不会自动进入 ROM DFU。即使计划只用 USB，也强烈建议给 PA13、PA14、
NRST、3V3、GND 留 SWD 测试点。

## 录音开发顺序

1. RTC、ADC、USB_DETECT。
2. microSD 持续写入与掉电恢复。
3. 先只启用 PB12/DFSDM Channel 1 的一个采样边沿，完成单声道 PDM + DMA 调试。
4. 再启用重定向 Channel 0 和相反采样边沿，分别验证两颗麦克风。
5. 先输出 16 kHz/16-bit PCM WAV 验证音频链路。
6. 再改 IMA ADPCM；Opus 留到稳定后再做。
7. 文件每 15-30 分钟切段，低电量时必须先停采集、补 WAV 头、同步并关闭文件。
8. 停止 PDM 时钟让麦克风休眠，然后 MCU 进入 Standby/Shutdown。

## 电池与时间

- PA0 读到约一半电池电压：`Vbat = ADC/4095 * Vref * 2`。
- 分压节点时间常数约 50 ms，冷启动至少等待 250 ms，并用最长采样时间和多次平均。
- VBAT 引脚接的是 3V3，不是原始电池。主电池断开或保护板切断后，RTC 会丢失时间。
- 每次连接 USB 时应由电脑写入可信 UTC；RTC 无效时不要伪造日期文件名。
